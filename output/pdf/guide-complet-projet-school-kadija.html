1. Vue générale

School Kadija est un site de gestion scolaire écrit en PHP, HTML et CSS. PHP construit les pages et applique les contrôles d'accès. HTML décrit les textes, formulaires, cartes et tableaux. CSS règle les couleurs, espacements, alignements et adaptations aux écrans.

État actuel : aucun accès à une base de données n'apparaît dans les fichiers. Les compteurs à zéro et les tableaux vides sont inscrits directement dans les pages; ils ne reflètent pas des dossiers réellement enregistrés.

Parcours d'une visite

index.php redirige vers l'accueil. Le bouton de connexion ouvre le formulaire. Après authentification, l'utilisateur arrive sur deux.php, puis peut ouvrir les écrans Élève, Enseignant ou Directeur. Une session est le mécanisme PHP qui mémorise l'état connecté entre les requêtes.

Notions PHP

$_GET lit les paramètres de l'adresse comme ?page=emploi; $_POST reçoit les champs du formulaire; $_SESSION conserve l'état de connexion; require_once charge un fichier une seule fois; header('Location:...') redirige le navigateur et exit arrête le script.

2. Connexion et sécurité

auth.php : fonctions partagées

  • school_admin_email() retourne l'adresse unique permise.
  • Le bloc de session active le mode strict, crée le dossier sessions si nécessaire et démarre la session PHP.
  • school_credentials_configured() vérifie l'adresse et la présence du hash dans SCHOOL_ADMIN_PASSWORD_HASH.
  • school_is_authenticated() teste le marqueur school_authenticated en session.
  • school_require_authentication() renvoie les visiteurs non connectés vers la page de connexion.
  • school_logout() vide les valeurs de session, expire le cookie et détruit la session.

connexion.php : traitement du formulaire

Le fichier inclut auth.php. Il traite d'abord une éventuelle déconnexion; si l'utilisateur est déjà connecté, il va au tableau de bord. Pour une requête POST, il lit l'e-mail et le mot de passe, valide le format de l'adresse, vérifie que la configuration existe et compare les identifiants.

hash_equals() compare l'adresse autorisée sans arrêt prématuré. password_verify() compare le mot de passe saisi avec l'empreinte cryptographique fournie par l'environnement. Si tout est correct, session_regenerate_id(true) renouvelle l'identifiant de session, le marqueur connecté est placé et le navigateur est redirigé vers deux.php.

Le formulaire HTML utilise les champs nommés email et motdepasse. Le navigateur aide à valider le format avec type="email" et le champ obligatoire, mais PHP refait ses contrôles. htmlspecialchars() protège l'insertion des messages dans la page.

Le script PowerShell demande le mot de passe et PHP en calcule le hash avec password_hash(). Le mot de passe en clair n'est pas stocké dans le code.
Limite : il n'y a pas de compteur d'échecs, de verrouillage temporaire, de récupération par courriel ni de comptes séparés par rôle.

3. Accueil et tableau de bord

index.php

Ce court fichier répond par une redirection vers accueil.php, puis termine son exécution. Il n'affiche pas de contenu.

accueil.php et accueil.css

L'accueil est une page de présentation : marque SK, message de bienvenue, carte de gestion scolaire, lien de connexion et pied de page. Le CSS organise l'en-tête et la zone principale avec Flexbox, crée les cartes et ajuste les colonnes selon la largeur de l'écran avec @media.

deux.php et deux.css

Cette page commence par charger l'authentification et appelle la protection. Elle affiche la barre latérale d'administration, des liens vers les trois profils, l'année scolaire et quatre statistiques. Les nombres sont écrits en dur à zéro. Le bloc « dernières inscriptions » est commenté en HTML et ne s'affiche pas; son lien vise inscriptions.html, qui n'existe pas dans le dossier examiné.

Le CSS donne une barre latérale, une zone principale, des cartes colorées, des styles de tableaux et des règles pour écrans moins larges. Les classes du HTML, comme .sidebar ou .carte, sont reliées aux sélecteurs CSS de même nom.

Comment lire le CSS

Un point cible une classe : .carte vise class="carte". Un nom sans point comme footer vise la balise HTML. :hover définit l'apparence au survol. display:flex aligne les éléments; display:grid crée des colonnes; @media adapte la mise en page aux mobiles. Le CSS ne contrôle jamais l'identité ou les données.

À ne pas confondre : les étiquettes statistiques donnent l'impression de données réelles, mais aucun calcul ou stockage n'est associé actuellement.

4. Les espaces par profil

eleve.php avec eleve.css

La page vérifie la session, initialise un profil minimal et choisit entre le tableau de bord et l'emploi du temps avec le paramètre page. Elle affiche des compteurs d'exemple et un tableau vide. Le CSS met en forme profil, menu, cartes et tableau; il empile les éléments sur petit écran.

Erreur possible : la session initialise nom mais le HTML affiche aussi $_SESSION['eleve']['classe']. Cette clé n'est définie nulle part dans l'initialisation actuelle; PHP peut donc afficher un avertissement. Il faut lui donner une valeur ou ne pas l'afficher.

enseignant.php avec enseignant.css

Les vues autorisées sont dashboard, classes, emploi et evaluations. Une valeur inconnue revient au tableau de bord. Les cartes, raccourcis et tableaux sont de la maquette; les lignes affichent qu'aucun élève, cours ou test n'est disponible.

directeur.php avec directeur.css

Les vues sont tableau de bord, classes, personnel et fiche établissement. Les tableaux sont vides et certains renseignements indiquent « À renseigner ». Le titre est échappé avec htmlspecialchars(). La navigation visible ne propose que le tableau de bord et le retour; les autres vues restent accessibles en ajoutant ?page=classes, ?page=personnel ou ?page=fiche à l'adresse.

Important pour les rôles

Les trois espaces ne correspondent pas encore à trois comptes ni à trois niveaux de permission. Ils utilisent tous la même authentification administrateur et partagent donc le même contrôle d'accès.

5. Scripts, logo et fichiers annexes

demarrer-serveur.bat

Le fichier batch Windows se place dans le dossier du projet, lance PowerShell avec le script de démarrage et garde la fenêtre ouverte pour montrer les erreurs.

demarrer-serveur.ps1

  1. Vérifie la présence de PHP à C:\xampp\php\php.exe.
  2. Demande le mot de passe en saisie masquée.
  3. Fait calculer son hash par PHP.
  4. Efface la variable temporaire et libère le tampon contenant le secret.
  5. Lance le serveur PHP local sur http://localhost:8000/.

Cette méthode suppose que XAMPP se trouve à cet emplacement. Il faut laisser la fenêtre ouverte pour utiliser le serveur; Ctrl+C l'arrête.

logo-school-kadija.svg

Un SVG décrit une image vectorielle par balises et formes. Ici, un bouclier bleu contient un bâtiment blanc avec une porte dorée. Le format peut être agrandi sans pixellisation. Les pages actuelles affichent souvent les initiales SK en texte plutôt que ce fichier.

make_explanation_pdf.php

C'est un outil annexe qui fabrique un ancien guide PDF consacré au blocage par adresse, surtout à auth.php et connexion.php. Ce n'est pas une page du site. Le script écrit lui-même des objets PDF, d'où sa structure plus complexe que les autres fichiers.

Dossiers

sessions stocke des données de session si PHP peut y écrire. output/pdf contient des PDF et fichiers de sortie précédemment créés; ils ne sont pas nécessaires pour afficher l'application.

Ordre conseillé pour comprendre le code

  1. Commencer par index.php, puis accueil.php.
  2. Lire le formulaire et les contrôles dans connexion.php.
  3. Voir les fonctions réutilisées dans auth.php.
  4. Suivre le contrôle d'accès dans deux.php.
  5. Ouvrir un espace comme enseignant.php, puis comparer ses classes HTML aux règles de enseignant.css.
  6. Enfin, lire les scripts de démarrage pour comprendre comment PHP est lancé.
Résumé mental : PHP décide de l'accès et du contenu; HTML décrit les éléments de la page; CSS les met en forme; la session mémorise la connexion. Les informations scolaires affichées sont encore des exemples statiques.
